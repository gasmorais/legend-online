# AMF remoting (Flash Remoting)

The client keeps a second, minor channel next to the game socket: Flash Remoting over AMF3.
This page lists the transport settings and every wrapper method of `CastleServiceManager`,
with the remote call it issues and the classes that call it. Generated by `tools/map.py`.

Related: [socket protocol](socket.md), [protobuf messages](proto.md),
[HTTP routes](../routes/routes.md), [architecture overview](../docs/overview/architecture.md).

Sources (relative to `decompiled/core_module/scripts`): `yishi/service/services/ServicesAmf.as`,
`yishi/service/managers/CastleServiceManager.as`, `AmfResponder.as`.

## Transport

- `NetConnection.connect(CastleServicePath)`, where `CastleServicePath` is
  `http://s1264oas.creaction-network.com/messagebroker/amf` (set in `Yishi.__coreLoadCompleteHandler`).
  Encoding is AMF3, standard Flash Remoting (BlazeDS).
- Every call targets the fixed destination **`ServerRequest`**:
  `NetConnection.call("ServerRequest.<method>", responder, ...args)`.
- `OuterCityServicePath` exists in `config.xml`, but no decompiled code reads it.
- A success reaches `AmfResponder.onResult(responder)` with `responder.result`; a failure reaches
  `onError` with `responder.error`.
- `_key` and `_uid` are `userInfo.key` and `userInfo.userId` from login (`CastleServiceManager.setup`).

## Notes

- Only methods with callers are used at run time; the rest of the game traffic goes through the
  socket on port 5004.
- `renamePet` and `renameChild`: `result == 3` means success (`pet.renameFrame.describt08`); any other
  value is an error. Before the call, the client validates the name over HTTP with
  `{REQ}nicknamecheck` (`nickname=<name>`, XML response attribute `@value`).
