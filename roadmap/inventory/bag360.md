# Security privilege pack ("Pacote de Previlégio de Segurança", client package `bag360`)

Module of [README.md](README.md). Six level gated reward packs (levels 5, 10, 20, 30, 40, 50) of the "360 privilege" partner program. The client package is assigned to inventory; the protocol package `privilege` and the VIP variant `bag360_vip` belong to [../vip/README.md](../vip/README.md).

## 1. Overview

- The manager asks the claimed list at startup (`B3M:35-45`) and on frame open (`B3F:52-56`).
- Pack `i` (1..6) requires hero level `[5, 10, 20, 30, 40, 50][i-1]` (`B3M:83-96`); each pack can be claimed once; when all six are claimed the frame closes (`B3F:92-102`).
- Contents come from `PrivilegeDrops.xml` (`Bag360Template`: `ItemId`, `DropId`, `Order` = pack index, `Count`, `Job` CSV) filtered by the hero class group (1/4 -> "1", 2/5 -> "2", 3/6 -> "3") (`B3I:159-217`). The XML is empty in this build.
- No toolbar button or other caller opens the `bag360` controller in this build (`FrameControllerManager` case "bag360" exists, `decompiled/core_module/scripts/yishi/manager/FrameControllerManager.as:1350-1351`); the feature is effectively unreachable but the startup request is still sent.

## 5. Rules and formulas

- Pack levels: 1 -> 5, 2 -> 10, 3 -> 20, 4 -> 30, 5 -> 40, 6 -> 50.
- One claim per pack per player; contents by class group.
- Assumption: only players flagged as privilege members (`isPrivilege`) may claim.

## 7. Persistent state

```sql
CREATE TABLE inventory.privilege_pack_claims (
  player_id   INTEGER     NOT NULL REFERENCES player.players(player_id) ON DELETE CASCADE,
  pack_index  SMALLINT    NOT NULL CHECK (pack_index BETWEEN 1 AND 6),
  claimed_at  TIMESTAMPTZ NOT NULL DEFAULT now(),
  PRIMARY KEY (player_id, pack_index)
);
```
