# Conventions

Rules fixed by the coverage audit. `roadmap/COVERAGE.md` (generated by `tools/coverage.py`) lists every opcode, registered screen and template file that no roadmap document mentions yet.

## Player id

PostgreSQL `BIGINT`, Rust `i64`, INT32 on the wire (`PlayerInfoMsg.userId #1`, also `SimplePlayerInfoMsg.userId #1`). Older documents wrote `integer`; `BIGINT` is the rule and gets fixed in place when a file is edited.

## Package registry

`roadmap/features.json` is generated by `tools/featuremap.py` from the `FEATURES` table and must never be edited by hand. Every client package and every protobuf package belongs to exactly one feature; the script fails while any package with at least two client classes or any proto package is unclaimed.

## Protobuf keys

`protocol/proto.json` keys a message by its simple class name. When two proto packages declare the same class name, every message after the first carries its package prefix: 21 keys such as `item.ItemInfoMsg`, `simple.PropertyMsg`, `party.OrderInfoMsg`. A nested class folder extracted next to its parent file (`proto/castle/CastleYieldMsg/WildYieldMsg.as`) belongs to the outer package, not to a package named after the file.

## Opcode table

`protocol/opcodes.csv` takes `dir` from the constant file the row comes from: `ProtocolType` rows are `send` (client requests), `AcceptProtocolType` rows are `accept` (server pushes and the legacy lookup table). `tools/navmap.py` indexes the table as `(dir, code) -> name` with the last row winning, so an alias name must sit before the canonical row; code 4552 carries two names (`U_C_SKY_TRIAL_INFO` before `U_C_RES_SINGLEPASS_INFO`).

## Shared messages

- Package `party` is owned by the fantasy bar (`magicpub`, feature `fantasy-bar`) and shared with the rave party (`RavePartyManager`, feature `seasonal-events`). A rule that mentions `OrderInfoMsg` means `party.OrderInfoMsg`.
- Homonym donors: bag items use `SimpleItemInfoMsg`; `PropertyMsg.temp_data` aliases `simple.PropertyMsg.param1`.
- Proto packages claimed by two managers (like `party`) stay in one feature and are listed here.

## Documentation

Concise semantic English, no em dashes or en dashes. Game strings in pt-BR and Chinese stay verbatim. Client classes cite `file:line`. Every module file lives in `roadmap/<feature>/` and follows the feature `README.md` structure: routes, protobuf messages, client classes, server responses, rules, templates, PostgreSQL tables, checklist.
