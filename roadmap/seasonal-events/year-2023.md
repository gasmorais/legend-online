# Anniversary celebration 2023 ("Aniversário", 周年庆典)

Feature `seasonal-events`, module `year-2023`. Client package `year2023` (`M3/year2023/{frame,view,item,ui,crl}/*`), shared `CM/managers/YearActiveManager.as` (`YAM`), `CM/mvc/module/year2023/YearActiveModel.as`, `YearActivityOp.as`, controller `CM/mvc/controler/YearActiveController.as`. Proto `activity.YearActivityMsg`, `player.PlayerOpMsg`.

Ownership split: the 9728/551 protocol and the per player state are specified in [../daily-activity/year-activity.md](../daily-activity/year-activity.md); this module owns the screens, the reward rules and the configuration.

Conventions: see [README.md](README.md). `M3` = `decompiled/m3/scripts`.

## 1. Overview

The anniversary event (`year_time` 2023-05-22 .. 2023-06-05). An entry frame lists six sub-events (`yearactivity.type1..6`):

| # | pt-BR | Mechanic | Frame / owner |
|---|---|---|---|
| 1 | "Presente de Check-in" | 14 day check-in with a free track and an advanced (paid) track; missed days can be made up for diamonds | "Day" frame, this module |
| 2 | "Mini game aleatório" | Daily random mini game (star area mini game); after a pass claim warrior points | entry item, this module (game client in [../cosmos/stararea.md](../cosmos/stararea.md)) |
| 3 | "Caça-Tesouro" | 15 floor treasure hunt: 9 boxes per floor opened with keys (-1801 "Chave de Baú"); best prize grows with the floor | "Look" frame, this module |
| 4 | "Exploração de Aniversário" | Dark maze with anniversary texts | [../mazes/dark-maze.md](../mazes/dark-maze.md) |
| 5 | "Coleção Comemorativa" | Event shop (anniversary coins, keys, collection boxes) | "Shop" frame; boxes in [../hermitage-war/seven-year-event.md](../hermitage-war/seven-year-event.md) |
| 6 | "Gashapon da Sorte" | Spend anniversary coins ("Moedas de Aniversário") for 1 or 10 draws from `YearEggDrop`; milestones at 1/5/10/15 draws | "Egg" frame, this module |

Top tool bar key `sevenyear` (TopToolBtnInfo 2061 "周年庆") opens it (`TopToolsBar.as:1482-1483`), visible when `YearActiveManager.isOpen` (`TopBtnCheckShowHelper.as:397-398`), set by the 4590 push with `param1 = 2061` (`YAM:81-92`). `YearActiveModel` also rewrites dark maze texts with the anniversary name (`YearActiveModel.as:1-25`).

## 3. Routes (client to server)

Route: **9728 (0x2600) `C_YEAR_ACTIVITY_CLIENT_OP`**, body `player.PlayerOpMsg`, sender `YearActiveManager.doSomething(op, id = -1)` (`YAM:99-105`): sets `op (#1)` and `id (#5)` (`-1` when omitted).

| op (`YearActivityOp`) | UI control | Call site | Client checks | id | Expected response |
|---|---|---|---|---|---|
| 1 OPEN | (constant; not sent by this client) | | | | 551 *(assumption: the server pushes 551 at login and on window open)* |
| 2 CHECKIN_GET | day "claim" | `YearActivePrivateItem.getClickHandler` (`item/YearActivePrivateItem.as:110-113`) | enabled for state 1, or state 2 with the advanced track bought | day (`Gear`) | 551 `opType 2` |
| 3 CHECKIN_ONEKEY_GET | "one key" | `YearActiveDayView` (`view/YearActiveDayView.as:234-237`) | enabled when any day is claimable | -1 | 551 |
| 4 CHECKIN_REGET | make up a missed day | `YearActivePrivateItem.bqCallHandler` (`:91-108`) | diamonds >= `year_checkin_buy[1]` (100) else recharge alert; confirm "yearactivity.buqian.ContentText" | day | 551 |
| 5 CHECKIN_BUY | buy advanced track | `YearActivePrivateCItem` (`item/YearActivePrivateCItem.as:88-106`) | confirm "yearactivity.day.AdvanceAlert" with `year_checkin_buy[0]` (800) | -1 | 551 (`buyCheckin = true`) |
| 6 GAME_GET | mini game claim | `YearActive2UI` (`ui/item/YearActive2UI.as:143-146`) | passed (`isGamePassed`) and `miniGameState == 0` | -1 | 551 (`miniGameState = 1`) |
| 7 BOX_OPEN | click a box | `YearActiveBoxItemUI` (`ui/item/YearActiveBoxItemUI.as:85-92`) | box not opened; keys | box position 1..9 | 551 with `boxInfo`, `showInfo` |
| 8 BOX_ONEKEY | "open all" | `YearActiveLookView.xClickHandler` (`view/YearActiveLookView.as:246-266`) | keys >= remaining boxes, else "Chaves insuficientes. Deseja comprar?" opens the shop | -1 | 551 |

| 10 EGG_START | gashapon x1 / x10 | `YearActiveEggView` (`view/YearActiveEggView.as:210-266`) | anniversary coins >= `year_gacha_extract` x count, else "Moedas de Aniversário insuficientes. Deseja comprar?" | 1 or 10 | 551 with `eggCount`; bag pushes |

## 4. Server messages (server to client)

| Opcode | Name | Message | Receiver | When | Reaction |
|---|---|---|---|---|---|
| 551 (0x0227) | U_C_YEAR_ACTIVITY_DATA | `activity.YearActivityMsg` | `YAM.__dataInfosHandler` (`YAM:55, 59-79`) | Login during the event, after every 9728, daily reset | Copies all fields; `miniGameState == 0` resets the local pass flag; notifies `EVENT_YEARACTIVITY_OP` with `opType` |
| 4590 (0x11ee) | U_C_TOP_TOOL_BTN | `simple.PropertyMsg` | `YAM.__topBtnHandler` (`YAM:56, 81-92`) | Window start and end, `param1 = 2061` | `isOpen = param7`, `openTime = param4`, `stopTime = param5` (the client parses `openTime` twice: `stopDate` equals `openDate`, a client bug with no effect on the server) |

`YearActivityMsg`: `opType` (#1, INT32) echoed op; `checkinInfo` (#2, STRING) "day,state\|..." with state 1 checked in, 2 free claimed, 3 all claimed (missing day = not checked in); `buyCheckin` (#3, BOOL) advanced track bought; `miniGameState` (#4, INT32) 0 not claimed today, 1 claimed; `boxInfo` (#5, STRING) opened boxes of the floor "pos,templateId,count\|..." *(assumption on fields after pos)*; `boxLevel` (#6, INT32) floor 1..15; `boxNext` (#7, BOOL) next floor allowed; `eggCount` (#8, INT32) gashapon draws done; `showInfo` (#9, STRING) positions opened by the last request "pos,pos"; `curDay` (#10, INT32) event day index.

## 5. Rules and formulas

Config (`ConfigInfos.xml`):

| Key | Value | Meaning |
|---|---|---|
| `year_time` | `2023-05-22 00:00:00\|2023-06-05 00:00:00` | Window |
| `year_checkin_buy` | `800,100` | Advanced track price, make up price |
| `year_game_time` | same window | Daily game availability |
| `year_game_score` | 200 | Points for the daily game |
| `year_gacha_buy` | 100 | Recharge bonus (coins per recharge unit) *(assumption)* |
| `year_gacha_extract` | 20 | Coins per gashapon draw |

- Check-in (`SpecialRewardTmpls` Type 2, 14 rows): day N becomes state 1 when the player logs in on event day N; free reward `FreeReward` (keys -1801), advanced `PayReward` needs `buyCheckin`. Make up a past day (`day < curDay`) for 100 diamonds.
- Treasure hunt (`SpecialRewardTmpls` Type 3, 15 rows by `Gear` = floor): each box costs 1 key; the floor has 9 boxes: one fixed `PayReward` and the `RandReward` items (count grows by floor) *(assumption: random placement)*; after opening the guaranteed prize box the next floor unlocks (`boxNext`).
- Gashapon: each draw consumes 20 coins and rolls `YearEggDrop` (dropId 21300001); milestone rewards `SpecialRewardTmpls` Type 4 at 1/5/10/15 draws.
- Mini game: one claim per day after a pass.

## 7. Persistent state

The protocol and the per player state are shared with [../daily-activity/year-activity.md](../daily-activity/year-activity.md), which defines the canonical table `daily_activity.year_activity_state` (check-in states as jsonb, advanced track flag, mini game state, box floor, box slots, opened slots, gashapon count). Do not create a second state table. This module adds only the event configuration and the per floor box contents that the client cannot see:

```sql
CREATE TABLE seasonal_events.year2023_box_contents (
  event_id     integer  NOT NULL,
  player_id    bigint   NOT NULL REFERENCES player.players(player_id) ON DELETE CASCADE,
  floor        smallint NOT NULL CHECK (floor BETWEEN 1 AND 15),
  position     smallint NOT NULL CHECK (position BETWEEN 1 AND 9),
  template_id  integer  NOT NULL,
  count        integer  NOT NULL,
  is_main      boolean  NOT NULL DEFAULT false,
  PRIMARY KEY (event_id, player_id, floor, position)
);

CREATE TABLE seasonal_events.year2023_egg_milestones (
  event_id   integer  NOT NULL,
  player_id  bigint   NOT NULL REFERENCES player.players(player_id) ON DELETE CASCADE,
  gear       smallint NOT NULL,
  PRIMARY KEY (event_id, player_id, gear)
);
```

`checkin_states` encoding (from `YearActivePrivateItem.updateBtnState`, `M3/year2023/item/YearActivePrivateItem.as:115-170`): key = day (`Gear`), value 1 checked in, 2 free reward taken, 3 all taken; a missing day is not checked in.

## 8. Backend implementation notes

The 9728 dispatcher is `daily_activity::year_activity::handle_client_op` ([../daily-activity/year-activity.md](../daily-activity/year-activity.md)); it calls these reward handlers owned here:

| Handler | op | Notes |
|---|---|---|
| `seasonal_events::year2023::grant_checkin` | 2, 3 | state 1 → grant `FreeReward` (and `PayReward` if bought) → state 2 or 3; state 2 with the advanced track → grant `PayReward` → 3 |
| `seasonal_events::year2023::make_up_checkin` | 4 | day < curDay and missing → 100 diamonds (`year_checkin_buy[1]`) → state 1 |
| `seasonal_events::year2023::buy_advanced` | 5 | not bought → 800 diamonds (`year_checkin_buy[0]`) |
| `seasonal_events::year2023::grant_game` | 6 | not claimed today → `year_game_score` |
| `seasonal_events::year2023::open_boxes` | 7 (one slot), 8 (all remaining) | one key (-1801) per box; roll contents into `year2023_box_contents`; set `boxNext` when the floor's main prize is out |
| `seasonal_events::year2023::next_floor` | 9 | `boxNext` → floor + 1 |
| `seasonal_events::year2023::gashapon` | 10 | `year_gacha_extract` coins x n → roll `YearEggDrop` x n → milestones (`SpecialRewardTmpls` Type 4) |

Login hook: mark the event day checked in. Collection boxes bought in the shop open through the shared 9695 service ([../hermitage-war/seven-year-event.md](../hermitage-war/seven-year-event.md)).
