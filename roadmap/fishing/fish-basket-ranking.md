## 1. Overview

Fish rewards go to a separate basket, bag type 23, shown in a 6 x 4 grid ("Cabaz"). Firing is blocked at 21 items. "Coletar Tudo" moves everything to the player's bags. The weekly ranking ("Ranking da Pesca") is a static XML file generated by the server and fetched over HTTP; positions 1 to 3 show title templates 100, 101, 102.

## 3. Routes (client to server)

### B1. Collect all (op 2 `GETALL_FISH`)
- UI: "Coletar Tudo" (`bottle.view.BottleStorageFrame.pickupButton`) in `FBF` (`FBF:62-65`).
- Sender: `FM.fishAction(2)`, C>S 9507 (0x2523) `C_FISH_POOL`, `FreshPoolMsg`: `op (#1, INT32)` = 2, `paras (#2, INT32, repeated)` empty.
- Client checks: button enabled only when bag 23 is not empty.
- Expected response: S>C 115 (0x0073) `U_C_BAG_MOVE_UPDATE`, `ItemMovedListMsg`: one `ItemMoveUpdateMsg` per removed bag 23 cell (`change_type (#1)` = 23, `change_obj_id (#2)` = 0, `change_pos (#3)`, no `item`) and one per destination cell in the main bag with `item`. The client fires `DELETE_FISH_BAG` (`GM:213-216`) and refreshes the frame. Virtual rewards (-4000 "Moeda do Jogo") credit the currency and push the currency update (assumption).

### B2. Ranking
- UI: "Ranking" link (`FF:424-427`).
- Route: HTTP GET `{TPL}fish.xml` (`PathManager.getFishOrderPath`, `decompiled/core_module/scripts/yishi/manager/PathManager.as:727-730`; `routes/routes.md:190`), loaded by `FC.loadFishOrderData` (`FC:61-90`).
- Format: any root, elements `FishScore` with attributes `UserId`, `Job`, `NickName`, `Score`, `ConsortiaName`, `Grades` (hero level), `FishGrades` (fishing level), `Order` (rank), `Index`, `FightingCapacity`, `IsVip` ("true"/"false"), `VipType` (1 or 2).

## 4. Server messages (server to client)

### S1. 115 (0x0073) `U_C_BAG_MOVE_UPDATE`
Generic bag update ([inventory](../inventory/README.md)). For bag 23, receiver `GM.__bagUpdateHandler` (`GM:101-235`) adds or removes cells and dispatches `DELETE_FISH_BAG`. Sent after catches (items into bag 23) and after B1.

## 7. Persistent state

Basket items: generic items table with `bag_type = 23`. Weekly score: `fishing.fishers.weekly_score` ([fish-pool.md](fish-pool.md)). Ranking snapshot:

```sql
CREATE TABLE fishing.weekly_ranking (
  week_start   DATE    NOT NULL,
  rank         SMALLINT NOT NULL CHECK (rank > 0),
  player_id    BIGINT  NOT NULL REFERENCES player.players(player_id) ON DELETE CASCADE,
  score        INTEGER NOT NULL,
  fish_level   SMALLINT NOT NULL,
  title_granted BOOLEAN NOT NULL DEFAULT false,
  PRIMARY KEY (week_start, rank),
  UNIQUE (week_start, player_id)
);
```

## 8. Backend implementation notes

| Route | Handler |
|---|---|
| 9507 op 2 | `fishing::fish_basket::handle_collect_all` |
| GET `/xml/fish.xml` | `fishing::fish_ranking::handle_ranking_xml` |

- Collect: one transaction moving every bag 23 item into free main bag cells (stack when possible), converting -4000 to the game box coin balance; push 115 and the currency update.
- Ranking: regenerate `fish.xml` periodically (assumption: every 10 minutes and at week rollover) from `fishing.fishers` ordered by `weekly_score DESC, level DESC`; top 50 (assumption). At week rollover snapshot into `fishing.weekly_ranking`, grant titles 100..102 ([hero](../hero/README.md) appell), reset `weekly_score`.
